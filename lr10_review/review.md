# Рецензія на чужий портфель

Каркас роботи ЛР10, ваша рецензія на портфель призначеного студента. Заповніть
розділи і зітріть підказки курсивом. Умова роботи лежить у матеріалах курсу,
`lr10_task.md`.

Прізвищ у цьому файлі немає: він публічний, і ви пишете про чужу роботу. Обидві
сторони називаються GitHub-логінами.

## 2. Наскрізність

Ключі між файлами звіряє валідатор правилами `X-1`, `X-2`, `X-3` і `X-14`, тому
тут один рядок з його підсумком:

*Наприклад: «валідатор наскрізних порушень не показав» або «`X-1`: `S-14` в
оцінках немає в беклозі».*

Нижче те, чого валідатор не бачить. У колонці «Стан» пишеться одне з трьох:
«сходиться», «не сходиться» або «файлів ще немає». Артефакт, термін якого не
настав, порушенням не є.

| Що перевіряли | Стан | Де саме дивились |
| --- | :-: | --- |
| Числа в межах варіанта: реліз проти ємності, години проти стелі, дата проти строку | | |
| Тема з кореневого README впізнається в артефактах | | |
| Критерії приймання перевірювані, а не «працює коректно» | | |
| Стейкхолдери статуту впливають на рішення, а не просто присутні | | |
| Дати прогнозу і дати плану описують той самий реліз | | |
